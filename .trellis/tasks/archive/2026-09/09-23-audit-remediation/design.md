# Design: layered fixes for the review findings and parallel integration

## Design premises

- **Fix incrementally** on the current dirty `dev` working tree; the original product code baseline is 17 modified + 4 untracked files (21 items), plus the planning files written by this task. Before coding starts the integrator saves the original change patch, copies of the four untracked files, and a SHA256/file list in the task directory (note the backup must not enter the release package and must not contain plaintext keys), then records `git status`. Workers write only their assigned files; rollback may only reverse-apply this round's increments or restore the comparison baseline, and must never overwrite the original dirty changes with a whole-file checkout. The shared `TestRunner.cs`, `STS2AIAgent.Tests.csproj`, `CHANGELOG.md`, and revisions to the original requirements are exclusively the integrator's.
- Work on top of the existing `IGameBridge`, `AgentRuntime`, `GameThread`, `DecisionLog.Recorded`, and the two MCP surfaces; new fields only add and never delete, ensuring old clients can still call `/companion/control` and `/strategy`.
- `run_id` is the identity of the current game state; `_runBoundary.RunId` is only the guard of the in-process auto-play session and must not be the sole source of identity for external actions. The action log and the current UI session are **two different concepts**.

## A. Session ownership and delayed logs (worker A; the base layer is delivered first)

`Router` reads the state run ID and executes `GameActionService.ExecuteAsync` once within the same game thread work unit before the action; after the action it accounts using the **pre-snapshot** ID rather than `_runBoundary.RunId`. It does not run the action again just to read the log, nor replay an HTTP action whose timeout is ambiguous. `OnSessionDecision` handles only decisions that match the active session identity; late entries from an old run still stay in the global diagnostic log but must not reload the old session. A real state read by `/state`/native MCP can establish the current run, and a late frame of `ObserveSessionState` from an old request must also avoid switching runs backwards. Session switching is driven by fresh state confirmation, not by arbitrary log events; tests cover unknown run, pure HTTP, Native MCP, new run, late old run, and recovery.

*Boundary*: worker A exclusively owns `Router.cs` (limited to `/action` and the necessary `/state` observation), `AgentRuntime.Session.cs`, `PlaySessionMemory.cs`, may review and patch the existing dirty `PlaySessionStore.cs` (only for confirmed legacy/collision regressions), and adds dedicated tests with the name prefix `AuditRemediationSession*Tests.cs`; it must not change `AgentRuntime.cs`, the shared test registration, or Native MCP files. The planning briefing fields and the companion control extension in Router are modified serially by the integrator after A delivers.

## B. Jev requests, planning, and risk readout (worker B)

Keep the `JevClient` play instance at `maxRetries: 0`; the 429 `JevException` of `JevClient` carries a safely parsed nullable `RetryAfterSeconds`, and `JevExecutionDecider` uses it to make at most **one extra call** to `IJevClient.SystemOneAsync`; backoff is at most 30 seconds and is cut off by the linked CTS of the whole turn. The unified end-to-end deadline takes the configured Jev request timeout (default 90 seconds), shared by the two HTTP calls + backoff, and must not restart the 90 seconds per attempt. The decider returns `RequestsSpent` by real attempts; cancellation, failure, and fallback must keep a complete receipt. Before the extra request, check through an injected `Func<int,bool>` or an equivalent callback whether `_budgetGuard.CheckBudget(extraRequests: attemptsSoFar + 1)` allows it; `_turnGate` already serializes local play/chat, other planning requests claim quota first, and `Observe` at the end of the turn commits uniformly, with no pre-deduction and no double billing. Non-rate-limit 4xx -> configuration, 408/429/5xx/timeout -> network, keeping the `RateLimited` classification to trigger backoff. The Ping on the settings page keeps its original independent retry policy and does not count toward the play budget.

Strategy refresh triggers on screen/Act/Boss change, consecutive low confidence, and every fixed N moves; the prompt uses the current strategy and the **same-run** recent decisions, sharing the briefing projection as much as possible to avoid data drift between MCP and the built-in planner. Choice + the optional Score danger level are turned into nullable values; total latency includes actual requests and waits. Do not treat score as confidence or as a replacement for Choice; the new nullable observation fields of `AgentTurnResult` should be compatible with old JSON.

*Boundary*: worker B exclusively owns `JevClient.cs`, `JevTypes.cs`, `JevExecutionDecider.cs`, `StrategyPlanner.cs`, `AgentLoop.Decision.cs`, `ExecutionDecision.cs`, `IGameBridge.cs` (only to add compatible fields to `AgentTurnResult`), and tests with the name prefix `AuditRemediationJev*Tests.cs`. B is also responsible for injecting, in `AgentLoop.Decision.cs`, the reading of the next-turn instruction from in-run chat (the integrator provides a same-run, read-once delegate); it must not change `AgentRuntime.Jev.cs`/`AgentLoop.cs` and must hand the exact signatures to the integrator. The existing `AuditStateAndPlannerTests.cs`/`AgentTurnIntegrityTests.cs` are upgraded uniformly by the integrator to fit the changes.

## C. Mode control, chat, and settings UI (worker C)

`AgentRuntime.PlayControl.cs` exposes an awaitable solo pause confirmation, using the 30-second cap adopted by the existing companion pause protocol; the companion uses the token-protected control API and confirms `phase=paused`. Switching is serialized: if the pause is unconfirmed, keep the old mode and visible state and do not start the other mode on its own; when an external control route starts play it must also check the current mode, avoiding bypassing the UI mutual exclusion. Teammate configuration syncs only the whitelist `DualLayerCoopEnabled`, `JevBaseUrl`, `JevApiKey`, `JevModel`, `JevConfidenceThreshold`, `JevRequestTimeoutSeconds`, and does not overwrite the whole companion settings; the key is already shared in the settings copy at two-instance launch, so what the token+loopback control route newly passes this time is only **in-run changes**, and keys in request bodies, responses, or errors must not be logged. A sync failure is visible and keeps the main instance's switch state but must not claim the teammate has switched; it takes effect from the next turn without interrupting an action already started. The old `{"running":bool}` remains valid, and control requests extended with an optional `settings` patch are implemented serially in Router by the integrator.

In-run chat is queued as a run-bound, capacity/length-limited, one-shot next-move instruction, and does not call `PlayIntent` or a play tool in this turn; cancellation/pause does not swallow unconsumed content, a run switch clears it, and idle chat keeps the existing "play one move on behalf only on an explicit phrase". Show a "takes effect next move"/failure receipt, and the user instruction entering the prompt must be marked as non-privileged content and redacted. The chat shows the compacted action execution result; keep the **single main model** of the newer live requirement and do not restore a separate play selector. The Jev panel shows the real actions, distribution, Score, and latency of the corresponding instance: the companion readout is passed by extending the `/companion/control` response over the existing token-verified local connection, or through a separate protected GET, shows an empty state when unconfigured/disconnected, and does not read stale data from the main instance.

*Boundary*: worker C exclusively owns `AgentOverlayHost.Pages.cs`, `AgentOverlayHost.Settings.cs`, `AgentOverlayHost.ChatCard.cs`, `CompanionConnection.cs`, may create `AgentRuntime.PlayControl.cs`, `AgentRuntime.CompanionSettings.cs`, the pure policies `PlayModeSwitchPolicy.cs` / `CompanionSettingsPatch.cs`, a new `AgentOverlayHost.PlayControl.cs` (to avoid the ratchets of Pages.cs 930/1000 and Settings.cs 922/1000), and tests with the prefix `AuditRemediationUi*Tests.cs`. Godot-dependent runtime partials **must not be added directly** to the C# test project; test compilation adds only the pure policy/patch files, and runtime wiring uses source contract tests. For new text ask the integrator to sync English in `Loc.Strings.Ui/Runtime.cs`. It must not change `AgentRuntime.cs`, `AgentRuntime.Session.cs`, `AgentRuntime.Jev.cs`, or `TestRunner.cs`; submit a wiring checklist.

## D. Native and Python MCP briefing (worker D)

First define a unified, backward-compatible projection: keep `strategy`, `dual_layer`, `jev_configured`, and add `run_summary`, `screen`, `recent_jev_decisions`, `confidence_trend` (null/empty collection when missing, never fabricated); B's built-in planner temporarily reads context from the same `GameBridge` state and the same-run DecisionLog, and D's external briefing uses a unified pure C# DTO/projection. Native MCP reads the current state read-only through `IGameBridge` and builds the briefing with the run-filtered decision log; the Python sidecar gets the same-named fields from `GET /strategy` and wraps them rather than inventing its own. Add real-equivalence tests for the new response fields (not just tool name/schema alignment) and redaction tests; sync the API docs and OpenAPI.

*Boundary*: worker D exclusively owns `NativeMcpServer.Tools.cs`, `AgentTools.cs` (only the briefing description/schema), the MCP Python client/server, `test_native_tool_alignment.py` and new dedicated tests, and `docs/api.md`; it may add a new pure `PlannerBriefingProjection.cs` and tests, agreeing on same-named fields with the integrator first. It must not write `Router.cs` or the native transport base files; it hands the needed HTTP response fields, projection signatures, and base wiring to the integrator, who wires Router serially after A completes.

## Integration and ownership

The integrator owns `AgentRuntime.cs`, `AgentRuntime.Jev.cs`, `AgentRuntime.Accounting.cs`, `AgentLoop.cs`, `AgentLoop.Probes.cs`, `PlaySessionRecord.cs`, `StrategyStore.cs`, `JevOptionEnumerator.cs`, `Companion/CoopLaunchPolicy.cs` (if truly needed), `NativeMcpServer.cs` (if D raises a signature need), `TestRunner.cs`, `.csproj`, `Loc.Strings.Ui/Runtime.cs`, `scripts/api_schema.py` and the generated `docs/openapi.json`, `CHANGELOG.md`, the existing `Audit*Tests.cs`, and the remaining shared source contracts. The existing dirty file baseline of this task must be backed up first. The chat instruction queue belongs to a new `AgentRuntime.PlayInstructions.cs` (integrator), B is responsible for the prompt read delegate of `AgentLoop.Decision.cs`, and A is responsible for preventing late frames of an old run from resetting the queue; the priority of entering the strategy/state summary must be explicitly reserved without calling PlayIntent. Merge A's run ownership first, then C's mode and chat and B's Jev budget, and finally D's briefing; all shared files are changed serially by the integrator, and workers do not cross boundaries. The new dedicated test files are compiled and run together by the integrator after registering them in `.csproj`/`TestRunner`, and workers only provide independent pure-logic checks or Python unit tests; their uncompiled tests must not be claimed as passing.

## Safety, compatibility, and rollback

- Do not open a second game or replace the live DLL; do not call the live Jev API; keys never enter logs, sessions, test fixtures, or the GET briefing.
- A failed mode pause fails closed and keeps the original mode; the second 429 request is not sent when either budget or total deadline is insufficient, leaving the first real receipt.
- New HTTP/MCP fields are nullable and old requests keep the original schema; session store write failures are best-effort, and the backup and old-path recovery keep the existing contract.
- Rollback only reverse-applies this round's increments and compares against the task-start patch/untracked-file snapshot, never restoring the original dirty working tree file by file; output a real offline verification and live to-test table.
