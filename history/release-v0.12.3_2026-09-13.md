## Why the Version Number Was Bumped

The build on the Workshop is the one the version number points at. PR #106 changed mod code (`AgentOverlayHost.cs`, `Loc.Strings.Ui.cs`); re-uploading it as `0.12.2` would have made the Workshop content differ from the `v0.12.2` GitHub artifact of the same name, while `/health` can report only one version number. Bumping a patch number gives the question "which version do I have" an answer.

## Cross-Check of the Mod Payload in the Two Artifacts

The DLL in the release directory and the DLL uploaded to the Workshop have the **same size (1187840) and a byte-identical PCK**, but the DLL SHA256 differs (release `40EDE117DD0D9E56` / Workshop `52D5D46B6D136C17`). A byte-by-byte comparison: **only 70 bytes of the whole file differ, concentrated in 7 contiguous ranges**, located exactly at the PE header timestamp (offset 136), the CLR module MVID, and the debug directory (PDB path).

That is, this is the normal difference from compiling the same source twice (a .NET build without the deterministic switch writes a fresh MVID and timestamp every time), not a code difference. If the next version needs the hashes on both sides to be exactly equal, deterministic builds must be turned on for `STS2AIAgent.csproj` (`<Deterministic>true</Deterministic>`; the .NET SDK has it on by default, so the difference here means it was not actually in effect or the output path took part in the hash); this round did not change it.

## Changes in This Upload (relative to v0.12.2 on the Workshop)

See the v0.12.3 section of [CHANGELOG.md](../CHANGELOG.md).

1. **The F8 window's invite button takes the same route as the API** (PR #106, author sachi4clover): the route split from #85 had so far reached only `POST /action`, and the in-game "Invite AI teammate" button still called the overload that only goes through auto-play. With the model unverified, clicking it was rejected by the old gate and the tab kept demanding a connection test first, while the same request through the API could bring up the teammate to wait for external takeover. Now the button picks its route by `FirstRunSetup.Evaluate(settings).ReadyToInvite`, the two explanatory lines in the tab switch with the route, and it is pinned by the source contract test `CoopRoute.OverlayInviteRoute` (restore the old form and that test turns red immediately).
2. **Packaged-links gate** (PR #105): adds the eighth offline gate `packaged-links`, which stops "a relative link newly written in the README that nobody rewrites" before packaging, instead of blowing up when cutting the release.
