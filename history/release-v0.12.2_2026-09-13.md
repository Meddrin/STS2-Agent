## Changes in This Upload (relative to v0.12.1 on the Workshop)

See the v0.12.2 section of [CHANGELOG.md](../CHANGELOG.md). This version is the "co-op relay":

1. **Inviting the AI teammate no longer requires a verified play model** (#85): when the model is unverified the teammate is still launched and still enters the map, then stops in place and waits for external takeover, and this path does not call a model at all (`STS2_AGENT_AUTOPLAY=0`).
2. **The main window gains `POST /teammate/control`** (#85), giving external agents a supported start / pause entry point that needs no teammate session token; the `companion` block of `GET /health` lets callers find the teammate's API port themselves.
3. **The teammate instance's own `POST /session/control` now has the same model gate** (#99): it was previously the only entry point that could start the in-process loop while bypassing validation; pausing is deliberately exempt from the gate.
4. **`combat.enemies[].base_max_hp`** (#101) separates the base HP before co-op scaling from the live scaled HP, so the metadata finally matches the live values.
5. **`item_ids` of `get_relevant_game_data` can be omitted** (#101) and is derived from the live state for the current screen; a paginated tutorial popup gives self-explanatory text on non-final pages instead of a `pending` that looks stuck (#101).

## Defect Found and Fixed During Packaging

On the first packaging run, `package-release.ps1` was stopped by the artifact check: `README.md links to missing packaged file 'docs/api.md'`.

- **Root cause**: when packaging, `Rewrite-PackagedReadmeLinks` uses a fixed string replacement table to rewrite the relative links in the README into absolute GitHub links; the table's keys have the form `"(./docs/api.md)"`, while the link #97 newly added to the README is `(docs/api.md)` **without `./`**, which did not hit the table, so the artifact was left with a link pointing at an unpackaged file.
- **Fix**: those links in both READMEs were changed back to the `./` form (consistent with the other links in the file), instead of adding a semantically duplicate rule to the table.
- **Preventing recurrence**: added an eighth offline gate, `packaged-links`. It parses the rewrite table out of `package-release.ps1` and **imports** the two manifests and the link rules from `check_release_package.py` (no copy-paste, so the gate cannot lie after the manifests drift), replays on the source documents the same rewrite as packaging, then checks that the remaining local links are all in the artifact. Destructive verification: changing the README link back to the bare form -> the gate exits with code 1 and reports `docs/api.md`; restoring it byte for byte makes it pass again (SHA256 identical to before). The self-test script `test-verification-gates.ps1` got a minimal update (the fixture gained the inputs the new gate needs, and case 6b moves the packaging script out of the way first).

## Upload Process (including one failure)

1. Package the workspace: `content/` byte sum 1225733.
2. The game was not running; Steam was running.
3. **The first upload failed 6 times in a row**, with `k_EItemUpdateStatusInvalid` / `k_EResultFail`. Steam's own log gave the cause: `Upload workshop item 3796486050 failed (Failed to initialize build on server (No Connection) )`: the Steam client's session to the UGC backend had gone stale, unrelated to the local artifact (the same flow worked when v0.12.1 was uploaded at 12:41, and a direct connection to `steamcommunity.com` also returned 200).
4. **Handling**: `steam.exe -shutdown`, wait for the process to exit completely, then relaunch (`AutoLoginUser = chartyr`, `RememberPassword = 1`, auto-login back into `U:1:460312869`), then rerun the same upload command and it succeeded: `k_EItemUpdateStatusUploadingContent` 1187294 bytes -> `UploadingPreviewFile` -> `Successfully uploaded`.
   -> Conclusion: **when a Workshop upload is stuck on `No Connection`, restarting the Steam client is an effective remedy**; there is no need to suspect the artifact.
5. Re-check: the Steam Web API `GetPublishedFileDetails` was used to verify `file_size` / `time_updated` / `visibility` / `tags` / `description`, and `file_size` equals the local content byte sum exactly.
